**soft refresh 的 p10 只有 24.0%，比 HARD 的 26.0% 还低**。原因：`management-pass.ts:565` 有字节相同守卫（`if (baselineBlockOf(target.text) === block) return false`），但守卫只在字节完全一致时生效；m[1] 每新增一条 compartment 就变一次字节，前缀即失效。

这是当前**最大的可优化项**：soft refresh 白付 12,822,491 tok，是 HARD 的 3 倍。

## 8. 结论

1. 代码改动（A→C）对**活跃对话**的缓存无影响，中位保真恒为 100%。
2. 83% 的缓存白付来自**空闲 ≥2min**，属 provider 缓存 TTL，非代码问题。
3. `ttlRebuild: true` **是正确的**：TTL 触发时 93% 已超 5min，重建零额外成本，还把 m[1] 折回 m[0]；单次白付从 77k 降到 38k。
4. **最大可优化项是 soft refresh**（`p10 = 24%`，白付 12.8M tok）。字节守卫挡不住 m[1] 增长导致的整体重写。
5. 压缩型断裂的性价比 1.26:1，正常。
